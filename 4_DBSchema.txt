### [panels]
  id                UUID  PK
  user_id           UUID  FK → auth.users.id  (UNIQUE, 1:1)
  name              TEXT
  industry          TEXT
  experience        TEXT  (경력 연차 등)
  bio               TEXT
  expertise         TEXT[]  (전문 분야 배열)
  bank_name         TEXT
  bank_account      TEXT
  bank_holder       TEXT

  streak_count      INT   DEFAULT 0  (최근 7일 내 submitted 건수)
  last_mission_date TIMESTAMPTZ
  badges            TEXT[]  DEFAULT '{}'
  phone             TEXT    (핸드폰 번호, 기업에게 비공개)
  phone_verified    BOOLEAN DEFAULT false
  ※ 009_gamification.sql 에서 streak_count / last_mission_date / badges 컬럼 추가
  ※ 012_panel_phone_public_profiles.sql 에서 phone / phone_verified 컬럼 추가

### [missions]
  id                 UUID  PK
  company_id         UUID  FK → companies.id
  title              TEXT
  type               TEXT  (예: 'landing_page')

  description        TEXT  (브리프)

### [feedbacks]
  id                    UUID  PK
  mission_id            UUID  FK → missions.id
  panel_id              UUID  FK → panels.id
  clarity_score         INT   (1–5, nullable — draft 중에는 null 허용)
  relevance_score       INT   (1–5, nullable)
  value_score           INT   (1–5, nullable)
  differentiation_score INT   (1–5, nullable)
  trust_score           INT   (1–5, nullable)
  strengths             TEXT  (draft 중 임시 저장용: JSON.stringify(comments), 제출 시 null)
  weaknesses            TEXT  (null 고정, 하위 호환용)
  suggestions           TEXT  ([레이블]\n코멘트 형식 5개 섹션 통합, 제출 시에만 기록)
  custom_answers        JSONB DEFAULT NULL  ← 014 추가 (LP 메인 의뢰 추가 질문 응답)
                               형식: [{questionId, questionText, type, answer}]
                               서브 미션(preference/pricing/email)은 각 응답 테이블의 custom_answers 사용
                               LP 메인 의뢰만 feedbacks.custom_answers 사용
  purity_passed         BOOL  DEFAULT false
  status                TEXT  ('draft'|'submitted'|'approved'|'rejected')
                               ※ draft: 수락 후 미완료 (패널이 수락하면 즉시 생성)
                               ※ CHECK 제약: feedbacks_status_check 로 4개 값 허용
  created_at            TIMESTAMPTZ DEFAULT now()

  ※ RLS: SELECT(인증된 전체), INSERT(패널), UPDATE(인증된 전체)
  ※ DELETE 정책 없음 → 수락 취소는 cancel_panel_feedback RPC(SECURITY DEFINER)로 처리

### [feedback_annotations] — 이미지 영역 어노테이션 (006_image_annotations.sql)
  id          UUID  PK

  y_pct       NUMERIC(6,2)  (상단 시작점 %)

  h_pct       NUMERIC(6,2)  (높이 %)
  dimension   TEXT  CHECK IN ('clarity','relevance','value','differentiation','trust')
  score       INT   CHECK BETWEEN 1 AND 5
  comment     TEXT
  created_at  TIMESTAMPTZ DEFAULT now()

  ※ RLS: panel_own_annotations(ALL), company_read_annotations(SELECT), admin_read_annotations(SELECT)
  INDEX: fa_feedback_idx, fa_mission_idx, fa_panel_idx

### SECURITY DEFINER RPC 함수 목록

  increment_mission_filled_count(mission_id UUID)
    → missions.filled_count +1 (패널이 직접 UPDATE 불가 → RPC 필수)

  increment_panel_mission_count(panel_id UUID)
    → panels.total_missions +1 (패널이 본인 panels 직접 UPDATE 불가 → RPC 필수)

  cancel_panel_feedback(p_mission_id UUID)
    → feedbacks DELETE (status='draft', 본인 panel) (DELETE RLS 없음 → RPC 필수)
    → 파일: supabase/migrations/004_cancel_feedback_rpc.sql

  update_panel_gamification(p_panel_id UUID)
    → trust_score / tier / streak_count / last_mission_date / badges 자동 계산·갱신
    → 피드백 제출 성공 후 ActiveMission.jsx에서 호출
    → 파일: supabase/migrations/009_gamification.sql

  get_panel_public_profiles(p_mission_id UUID) RETURNS TABLE(panel_id UUID, industry TEXT, experience TEXT)
    → 해당 미션의 feedbacks(status≠draft)를 제출한 패널의 공개 정보만 반환
    → 기업 Results.jsx에서 직군/경력 뱃지 표시에 사용 (이름·연락처·계좌 제외)
    → panels RLS가 기업의 직접 JOIN을 차단(D-28)하므로 SECURITY DEFINER RPC로 우회
    → 파일: supabase/migrations/012_panel_phone_public_profiles.sql

  get_shared_mission(p_token TEXT) RETURNS jsonb
    → 토큰으로 미션 조회 + purity_passed=true 피드백 집계 반환
    → 인증 불필요 (SECURITY DEFINER), /share/:token 공개 페이지에서 사용
    → 파일: supabase/migrations/010_sharing.sql
