## 서비스 개요

- 서비스명: Purity
- 성격: 전환율 최적화(CRO) 패널 서베이 SaaS MVP
- 목적: 기업이 자사 랜딩페이지/콘텐츠/가격 등을 실제 타겟 패널에게 검증받고,
         정량적 피드백(5개 축 점수)을 통해 마케팅 자산을 개선하도록 지원
- 사용자 역할: 3종 (company / panel / admin)

## 인증 흐름
================================================================

- 방식: Supabase Auth (이메일 + 패스워드 / Google OAuth)
- 회원가입(이메일): role 선택(company/panel) → signUp 호출 →
             DB 트리거(handle_new_user)가 panels 또는 companies 테이블에 레코드 자동 생성
             ★ 기업 가입 시 plan='free_trial'로 시작 (085) — 구 'starter' 자동 부여 폐지.
               무료 체험 = 첫 메인 의뢰 1회 무료(free_trial_used로 1회 제한). 상세는 1_PRD_company.txt 참조.
               (이메일=handle_new_user, OAuth=create_oauth_user_profile 둘 다 free_trial)
             ★ 패널 이메일 가입: CREDS 스텝(검증 서류 첨부 UI) 제거 (2026-05-28) — 서류는 가입 후 /panel/verify-docs에서 제출
               (File 객체 sessionStorage 직렬화 불가 이슈 제거, 이메일 가입도 가입→로그인→/panel/verify-docs 흐름으로 통일)
               ★ /panel/verify-docs에서 본인 연차(자격득실 확인서 기준, 2년차 이상)도 함께 입력 → 어드민이 PanelManagement에서 확정 (2026-06-12)
                 경력은 어드민 확정 항목으로 패널 자가 수정 불가. 확정 후 매년 자동 +1, 어드민 수동 상·하향 가능 (migration 081)
- 로그인(이메일): signInWithPassword → user_metadata.role로 역할 판별 → 역할별 대시보드 리다이렉트
- 로그인(Google OAuth): ★ 신규
  · Login.jsx 상단 역할 선택(기업/패널) → "Google로 로그인" 버튼 클릭
  · localStorage('purit_oauth_role')에 role 저장 → signInWithOAuth({ provider: 'google' })
  · Google 인증 완료 → Supabase → /oauth/callback 리다이렉트
  · OAuthCallback.jsx: 신규 유저면 role 읽어 user_metadata 업데이트 + companies/panels 레코드 수동 생성
  · 기존 유저(role 이미 있음)면 바로 대시보드 리다이렉트
  · Supabase 대시보드 URL Configuration에 /oauth/callback 허용 URL 등록 필요
- 휴대폰 인증 (Mock OTP) ★ 신규 (migration 101/103, 2026-06-16)
  · 가입 시 휴대폰 인증 필수 — 알림톡 도달 위해 전 사용자 휴대폰 확보 (보안 목적 아님: 패널은 서류 검증이 더 강함)
  · 이메일 가입: Signup 폼에 휴대폰 입력 + "인증번호 받기"(800ms)+6자리 확인 → 인증 완료 전 가입 차단
    인증 번호를 signUp user_metadata(phone·phone_verified)로 전달 → handle_new_user 트리거가 panels/companies에 저장
  · Google 가입: 폼을 안 거치므로 가입 후 /verify-phone 게이트에서 본인 인증 → save_my_phone RPC(본인 행만)로 panels/companies/team_members에 저장
  · 게이트: RoleRoute가 user_metadata.phone_verified !== true 인 기업/패널을 /verify-phone로 (admin 제외).
    인증 시 supabase.auth.updateUser로 metadata.phone_verified 갱신 → 통과. 라우트마다 DB 조회 없이 metadata로 판별
    · /verify-phone(VerifyPhone.jsx)은 마운트 시 DB가 이미 phone_verified면 metadata만 동기화 후 통과(기존 인증 패널 재입력 불필요)
  · Mock: 6자리 아무 숫자 통과 (실 SMS 게이트웨이 연동 전). 연타 가드(submittingRef) 적용
- 세션: getSession() 초기 로드 + onAuthStateChange 실시간 구독
- 접근 제어: RoleRoute 컴포넌트 — 비인증 시 /login 리다이렉트,
             역할 불일치 시 해당 역할 홈으로 리다이렉트,
             기업/패널 휴대폰 미인증 시 /verify-phone 리다이렉트 (admin 제외)
