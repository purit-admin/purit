## 사전 준비
================================================================

[ㅇ] 테스트 환경 확인
    - 브라우저: Chrome 최신 버전 (DevTools 열어두기 — Console 탭 에러 모니터링)
    - Supabase Dashboard 접속 — Table Editor / Auth 탭 열어두기
    - 테스트 이메일 계정 최소 4개 준비:
        · 기업 오너용   (예: test-company@gmail.com)
        · 기업 팀원용   (예: test-member@gmail.com)
        · 패널 1번용   (예: test-panel1@gmail.com)

## 섹션 4. 기업 포털 — 의뢰 등록
================================================================

──────────────────────────────
4-A. 메인 의뢰 (LP검증) 등록 — 전체 Step 완주
──────────────────────────────

[ㅇ] 4-A-1. /company/new 접속 → 소개 페이지 (list 뷰) 표시 확인
[ㅇ] 4-A-2. "새 의뢰 등록" 또는 "+" 버튼 클릭 → form 뷰 진입

[ㅇ] 4-A-3. Step 0 — 서비스 정보 & 타겟 페르소나:
    - 산업군 드롭다운 클릭 → 20개 칩 표시 확인
    - 산업군 선택(예: SaaS) → 서비스명/연령대/월소득/직군/타겟상세/브리핑 placeholder 자동 교체 확인
    - "✏️ 직접 쓰기" 클릭 → 텍스트 입력 모드 전환 확인
    - 서비스명 입력 → 랜딩페이지 URL 입력 (선택)
    - 연령대/월소득/직군/타겟상세 입력
    - "다음" 클릭

[ㅇ] 4-A-4. Step 1 — 소재 업로드:
    - 이미지 업로드 (최대 3장, accept=image/* — JPG/PNG/WebP 등)
    - 4장 업로드 시도 → 차단 확인
    - 20MB 초과 파일 → "○○이 20MB를 초과합니다." 에러 확인
    - 20MB 이하 큰 파일 → 자동 압축(compressImage) 후 업로드되는지 확인
    - FOCUS 검증 포인트 2개 이상 선택
    - 브리핑 텍스트 입력
    - "다음" 클릭

[ㅇ] 4-A-5. Step 2 — 질문 설정:
    - "내 커스텀 질문" 아코디언 열기 (초기엔 비어있음)
    - QUESTION_TEMPLATES.lp 아코디언 열기 → 질문 목록 표시 확인
    - 질문 3개 선택 → "3/5 선택됨" 배지 확인
    - 서술형 질문 3개 선택 시도 → 2개 초과 차단 확인
    - "질문 만들기" 인라인 섹션에서 새 질문 작성 + "추가" 클릭 → localCustomQs에 추가 확인
    - "템플릿에 저장 →" 클릭 → ConfirmModal → 확인 → DB에 저장 + "내 커스텀 질문"에 표시 확인
    - "다음" 클릭

[ㅇ] 4-A-6. Step 3 — 패널 설정:
    - 슬라이더 10~30명 드래그 테스트
    - Starter 플랜: 15명 초과 드래그 후 마우스 놓기 → 15명으로 snap-back + 업그레이드 팝업 확인
    - 경력 선택 버튼: 주니어/미들 선택
    - Starter 플랜: 시니어/C레벨 클릭 → 업그레이드 팝업 표시 (체크 없음) 확인
    - 하단 sticky 크레딧 계산기 실시간 변동 확인
    - "다음" 클릭

[ㅇ] 4-A-7. Step 4 — 검토:
    - 모든 입력값 요약 표시 확인
    - "⚡ 안내" 문구 확인
    - "🔒 수정 잠금 안내" + "조기 종료 시 크레딧 환불 불가" 문구 확인
    - 크레딧 부족 시 빨간 경고 배너 표시 확인 (크레딧=0일 때)
    - "의뢰 제출 →" 버튼 클릭 → ConfirmModal → 확인
    - 제출 성공 → /company 대시보드 이동 확인

[ㅇ] 4-A-8. 대시보드 "전체 의뢰 현황" → 진행 탭에 새 의뢰 카드 표시 확인
[ㅇ] 4-A-9. 카드 상태 뱃지 "매칭 대기" (gray) 확인 (filled_count=0이므로)
[ㅇ] 4-A-10. 어드민 /admin/notifications → "새 의뢰 등록" 알림 수신 확인
[ㅇ] 4-A-11. Supabase missions 테이블에 status='active', type=NULL/landing_page 확인
[ㅇ] 4-A-12. credits_reserved 컬럼에 예상 소모 크레딧 값 확인

──────────────────────────────
4-B. 메인 의뢰 — 임시저장 & 이어쓰기
──────────────────────────────

[ㅇ] 4-B-1. /company/new → form 뷰 → 서비스명만 입력 후 "취소/목록으로" 클릭
[ㅇ] 4-B-2. 3버튼 모달 표시 확인 ("임시 저장 후 나가기" / "저장 없이 나가기" / "계속 작성하기")

[ㅇ] 4-B-5. "이어 작성하기 →" 클릭 → form 뷰 + 이전에 입력한 서비스명 복원 확인

4-C. 소재 A/B 비교 등록
──────────────────────────────

[ㅇ] 4-C-1. 사이드바 "소재 비교 A/B" → /company/preference → "새 테스트" 버튼 클릭
[ㅇ] 4-C-2. Step 0: 의뢰명(선택) + 소재 유형 선택 + 소재 A/B 텍스트 입력 + 이미지 업로드(선택) + 제품설명 + 산업군
[ㅇ] 4-C-3. Step 1: 질문 설정 (최대 5개)

## 섹션 15-C. 구독 결제 재설계 — 플랜 변경 누적 / 월 갱신(매월 리셋·구매분 보존) / 다운그레이드 차단 / 월간·추가 구분 ★ 신규 (096)
================================================================

목적: "플랜 변경 시 잔여 크레딧이 사라지던" 버그를 고친 새 구독 모델 전체를 검증한다.
      ① 업그레이드 = 누적(잃지 않음) ② 월 갱신 = 매월 리셋하되 구매 충전분은 보존
      ③ 상위→하위 다운그레이드 즉시 차단 ④ 월간(구독)/추가(구매) 크레딧 구분 표시 + 사용 확인 모달.

용어: '월간 크레딧'=플랜 구독 지급분(매월 리셋) / '추가 크레딧'=별도 구매 충전분(리셋돼도 보존).
      파생식: 월간_잔여 = 잔액 − addon_credits(0 미만이면 0) / 추가_잔여 = min(addon_credits, 잔액).

사전 준비:
- ★ 마이그레이션 096_subscription_billing.sql을 Supabase SQL Editor에서 실행 완료(미실행 시 addon_credits 컬럼 없음 → 충전·결제 실패).
- Starter로 시작 가능한 기업 계정 1개(또는 free_trial → Starter 결제로 진입).
- Supabase Table Editor: companies(plan·credit_balance·addon_credits·plan_started_at·next_billing_at·plan_billing_cycle) 탭 열어두기.
- DevTools Console 열어두기(다운그레이드 RPC 가드·갱신 RPC 수동 호출용).
