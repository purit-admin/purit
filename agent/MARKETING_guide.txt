## 기본 워크플로우

[단독 작업]
@스티브 → 리서치만 필요할 때
@잡스   → 캠페인 기획만 필요할 때
@뱅크시 → 소재 제작만 필요할 때
@셜록   → 집행 데이터 분석·판결만 필요할 때

[팀 협업 — @Team 호출 시 순서]
1. 스티브: 시장·타겟 리서치 (Tavily 검색) → Kill/Go 판정 + JTBD + 경쟁사 맵 + 예산 역산
2. 잡스: 스티브 결과 반영해 캠페인 기획 (메시지 전략 + 채널 설계 + 경험 아키텍처 + Kill Switch 설정)
3. 뱅크시: 잡스 기획서 기반 소재 제작 (카피 + 이미지)
4. 사용자: 광고 집행
5. 셜록: 실측 데이터 분석 → Kill/Pivot/Scale 판결 → 팀 피드백
6. 결과물 통합 후 다음 사이클 반복

## 광고 캠페인 루프
1. 스티브 → 타겟·경쟁사 리서치 + 허용 CPA 역산
2. 잡스 → 캠페인 기획 (메시지 방향 + 채널 전략 + Kill Switch 수치 설정)
3. 뱅크시 → 소재 제작 (퍼널 단계별 A/B 카피 + 이미지)
4. 사용자 → 광고 직접 집행 (Meta·LinkedIn 등)
5. 셜록 → 실측 데이터 분석 + Kill/Pivot/Scale 판결
6. 셜록 → 스티브(타겟 재정의) / 잡스(메시지 피벗) / 뱅크시(소재 교체) 각각 피드백
7. 반복

## 성과 데이터 전달 방법
광고 집행 후 아래 형식으로 셜록에게 전달:

  ★ 소재명 추적성 원칙 (셜록의 Reason-Why 분석을 위한 필수 조건)
  소재명은 아래 두 값을 함께 기재해야 한다. 임의 입력 금지.
    - 잡스의 캠페인 브리프에 명시된 '방향 A/B/C + 퍼널 단계'
    - 뱅크시의 산출물 파일명 (YYYYMMDD_채널_퍼널단계_방향.ext)
  예) 소재명: [방향A_TOFU_공포자극] 20260601_LinkedIn_TOFU_A.png

  잡스 브리프·뱅크시 파일명 없이 "배너1", "소재A" 등 임의 명칭 입력 시
  셜록은 심리적 프로파일링 수행 불가로 수사를 거부하고 정확한 명칭 재요청.

"@셜록 아래 데이터 분석해줘
소재명: [잡스 방향 + 뱅크시 파일명]
집행 기간: [YYYY-MM-DD ~ YYYY-MM-DD]
집행 채널: [LinkedIn / Meta / Google 등]
퍼널 단계: [TOFU / MOFU / BOFU]
예산 소진: [₩XXX,XXX]
노출: [숫자]
클릭: [숫자]
전환(트라이얼 신청): [숫자]
유료 전환: [숫자]
랜딩 체류 시간: [X초 / 미측정]
이탈률: [X% / 미측정]
기타: [외부 변수 메모]"

## 결과물 저장 규칙
- 리서치: agent/tasks/YYYYMMDD_research_주제.txt
- 소재기획: agent/tasks/YYYYMMDD_creative_주제.txt
- 분석: agent/tasks/YYYYMMDD_analysis_주제.txt
- 이미지: agent/tasks/assets/YYYYMMDD_소재명.png

## 메모리 업데이트 규칙
작업 완료 시 agent/memory/team_memory.txt에 추가:
[날짜] @에이전트 [작업명]: 핵심 인사이트 1~3줄

## 에이전트 성장 규칙
- 각 agent/*.txt의 LEARNED 섹션에 작업별 학습 누적
- 5개 항목마다 레벨업
- Lv.1 신입 → Lv.2 주니어 → Lv.3 미들 → Lv.4 시니어 → Lv.5 마스터
- 레벨업 시 산출물 품질 기준도 함께 높아짐

## 금지 사항
- API 키 코드·채팅에 직접 입력 금지 (.env에서만 관리)
- Supabase 데이터 수정·삭제 금지 (읽기 전용)
- 메모리 업데이트 없이 세션 종료 금지
- 이전 세션 확인 없이 즉시 작업 시작 금지

## ⭐ 팀 공통 행동 강령
################################################################

### 공통 확정 금지 원칙
직접 데이터(원문·DB 수치·캠페인 리포트)를 확인하지 않은 채
인사이트를 "사실"로 기재하지 말 것.
"아마 이렇게 될 것이다" / "이 업계는 보통 이렇다" 는 어떤 산출물에도 쓰지 않는다.
확인된 것은 "사실", 확인하지 않은 것은 "(추정)" 표기 필수.

### 산출물·메모리 대칭성 검증
저장한 파일(agent/tasks/)과 팀 메모리(agent/memory/team_memory.txt)에 기록한 인사이트가
1:1로 대응되는지 확인할 것.
  - 저장은 됐는데 메모리 없음 → 다음 세션에서 중복 작업 발생
  - 메모리는 있는데 파일 없음 → 재현 불가

### 셜록 PIVOT 판결 시 라우팅 원칙 (명령 분기 기준)

셜록이 🟡 PIVOT을 선언하면 아래 분기를 따른다. 잡스 우회 금지.

  ┌─────────────────────────┬────────────────────────────────────────┐
  │ PIVOT 유형              │ 라우팅 경로                             │
  ├─────────────────────────┼────────────────────────────────────────┤
  │ 방향성 전면 교체         │ 잡스부터 루프 재시작                    │
  │ (메시지 방향·타겟 변경)   │ 잡스 → 뱅크시 순서 필수                │
  ├─────────────────────────┼────────────────────────────────────────┤
  │ 동일 방향의 시각적 변형   │ 뱅크시 단독 즉시 수행 가능              │
  │ (훅 문장·비주얼·CTA만    │ 잡스 Big Idea 범위 내에서만 허용        │
  │  소폭 수정)              │ 방향이 바뀌면 즉시 잡스에게 에스컬레이션│
  └─────────────────────────┴────────────────────────────────────────┘

  판단 기준: "이 변경이 잡스의 Big Idea를 바꾸는가?"
    YES → 잡스 루프 재시작
    NO  → 뱅크시 단독 수행

### 캠페인 루프 무결성 체크
한 사이클(리서치→소재→집행→분석→개선)이 끝날 때마다 확인:
  ✓ 스티브의 인사이트 → 잡스 캠페인에 반영됐는가?
  ✓ 집행 성과 → 스티브 다음 리서치 방향에 반영됐는가?
  ✓ 잡스의 소재 변경 이유 → 팀 메모리에 기록됐는가?
  ✓ 셜록의 PIVOT 판결 → 잡스 경유 여부가 라우팅 원칙에 따라 결정됐는가?
팀 메모리에 이 흐름이 기록되지 않으면 루프가 끊긴 것으로 간주.

### 수평 전개 의무 (전 에이전트 공통)
하나의 인사이트·소재·지표를 발견한 직후 멈추지 말고 자문:
  "이 발견이 다른 타겟 / 다른 채널 / 다른 소재에도 동일하게 적용되는가?"
있다면 즉시 확인. 첫 번째 발견으로 전체를 단정하지 말 것.

## ⭐ 퍼널 단계 정합성 규칙 (팀 전체 강제 적용)
################################################################

### 퍼널 3단계 정의
  TOFU (Top of Funnel — 인지):
    대상: Purit을 모르는 잠재 고객
    목표: 문제 인식 유발, 브랜드 각인
    KPI: 도달 / CPM / 브랜드 검색량
    소재 톤: 교육형, 공감형, 질문형. CTA 없거나 약하게.
    예: "B2B 광고, 감으로 만들고 계신가요?"

  MOFU (Middle of Funnel — 고려):
    대상: Purit을 알지만 비교 중인 고객
    목표: 차별점 각인, 신뢰 구축
    KPI: CTR / 랜딩 체류 시간 / 데모 신청
    소재 톤: 비교형, 사례형, 수치 강조.
    예: "사용자 인터뷰와 다른 점: 48시간, 10명, 5대 지표 정량 점수"

  BOFU (Bottom of Funnel — 결정):
    대상: 결제를 고려 중인 고객
    목표: 마지막 의심 제거, 전환 유도
    KPI: CPA / 전환율 / ROAS / LTV:CAC
    소재 톤: 직접적 CTA, 리스크 제거(무료 체험·보장·사례).
    예: "지금 신청하면 48시간 내 첫 리포트. 결과 없으면 환불."

### 퍼널 단계 미스매치 금지
  TOFU 소재에 "지금 바로 결제하세요" → 타겟이 아직 Purit을 모름. 신뢰 붕괴.
  BOFU 소재에 교육형 콘텐츠만 → 결정 직전 고객이 이탈.
  모든 소재·캠페인에 단계 태깅 후 KPI를 단계에 맞게 설정.

### 단계 확인 의무 (@Team 협업 시)
  스티브: 리서치 결과물에 "이 인사이트는 TOFU/MOFU/BOFU 중 어느 단계용인가?" 명시
  잡스:   캠페인 기획 방향 A/B/C 각각에 퍼널 단계 태깅 후 KPI를 단계에 맞게 설정

## ⭐ Purit 고유 데이터 활용 원칙 (최우선 차별화 무기)
################################################################

### 스티브 → 잡스 데이터 파이프라인 (사이클마다 실행)
Purit은 실제 B2B 마케팅 소재에 대한 5대 지표 점수 데이터를 보유한 유일한 서비스다.
이 데이터를 자사 마케팅에 쓰지 않으면 가장 큰 무기를 버리는 것이다.

  매 캠페인 사이클 시작 시 스티브가 아래를 실행:
  1. 팀 메모리 또는 사용자 제공 데이터에서 최근 5대 지표 점수 확인
  2. 가장 낮은 지표(pain point)과 가장 높은 지표(강점) 도출
  3. 업종별·직군별 점수 편차 확인
  → 잡스에게: "이 업종/직군에서 이 지표이 특히 약하다" 전달
  → 잡스: 해당 Pain Point를 캠페인 핵심 메시지로 설계

### 벤치마크 데이터를 사회적 증거로 활용
  내부 DB에서 추출 가능한 수치 예시:
  - "Purit 사용 기업 평균 5대 지표 점수 X점 → 개선 전 대비 Y% 향상"
  - "신뢰도 점수가 낮은 소재의 전환율은 높은 소재보다 Z% 낮음"
  이 수치는 경쟁사가 절대 보유하지 못한 독점 데이터다.
  스티브가 수치를 확인하면 잡스가 캠페인 메시지의 근거로 우선 활용.

### 역설적 포지셔닝 문구 (Purit만의 핵심 가치 명제)
  "AI가 광고 소재를 만들어주는 시대,
   그 소재를 실제 타겟이 어떻게 느끼는지 아는 회사는 없다.
   Purit은 안다."
이 포지셔닝은 모든 소재의 기저 메시지다.
잡스는 캠페인 방향 3개를 만들 때 이 가치 명제에서 벗어나지 않았는지 확인.
